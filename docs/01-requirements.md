# 需求规格

## 目标与范围

产品名称 iotwong，中文定位设备管理平台。默认语言简体中文，显示时区 Asia/Shanghai，可切换 UTC。两条独立验收线：A 自建定位平台；B 合宙活动作品。A 成功不能替代 B。

| ID | 优先级 | 用户需求与完成标准 |
|---|---|---|
| R01 | P0 | 本地账号安全登录/退出、会话过期恢复；管理员/查看者权限 |
| R02 | P0 | 合宙登录入口，用户提供演示账号在官方正常授权后可查看其真实设备；失败给真实错误 |
| R03 | P0 | 按数据源/项目/设备名或标识搜索、分页、筛选在线/离线/未知，展示最后通信与最后定位 |
| R04 | P0 | 地图聚合设备点、列表点击定位、地图点反选列表；无定位设备仍在列表，不能放在 0,0 |
| R05 | P0 | 设备详情侧栏：标识、来源、更新时间、在线依据、定位来源、精度、电量/信号（缺失为未知） |
| R06 | P0 | 自建设备 MQTT 接收、验证、幂等落库、实时位置推送；刷新页面可恢复 |

| R09 | P0 | Docker Compose 启动、健康检查、迁移、外置 PG 和全容器两种方式 |

## 信息架构与视觉规范

登录 → 工作台（设备地图为主）→ 设备列表 / 轨迹 / 报警 / 设置。桌面采用 224px 导航 + 320px 设备列表 + 自适应地图 + 360px 可关闭详情栏。小屏导航收起，设备列表为底部抽屉，详情单独 Sheet；地图始终能返回。

统一使用 shadcn-svelte 的 Button、Input、Select、Dialog、Sheet、Tabs、Table、Tooltip、Toast、Skeleton 和 Sidebar 组合管理台，不混搭其他 UI 库。以 CSS token 统一背景、前景、primary、border、success/warning/danger、8px 间距基线、10–12px 圆角；正文 14px，页面标题 24px。浅色默认、深色可切换，地图主题随之适配。图标采用同一 Lucide 风格。

地图区突出在线数、无定位数和最新更新时间，不堆叠无业务意义统计。定位状态与通信状态分开：设备在线不等于 GPS 已定位。颜色配文字/图标，不单靠红绿区分；键盘焦点可见，触控目标至少 44px，普通文本对比度目标 4.5:1。

## 状态与规则

- self-hosted 在线：最后有效通信距当前时间不超过 `max(3 × expected_report_interval_s,180s)`；超过离线，从未通信为未知。记录阈值来源，不能把历史导入时间当通信时间。
- Luatos：优先显示上游明确状态；没有状态字段时依据已核验的通信时间计算并标注推断；同步失败是独立状态。
- 演示数据：固定标注“历史回放”，不参与真实在线数量。回放模拟实时若开启必须显示“模拟”。
- 缺失电量不推导百分比；电压不是百分比。最后通信、采集、接收时间分别展示。
- 空数据给出接入/更换时间窗口动作；地图底图失败仍可看列表、坐标与轨迹表格。

## 非功能目标（待实测，不是现有能力）

测试基线先定 4 vCPU/8GB、局域网、10万导入点、1000设备。设备列表 p95 <500ms；24h 抽稀轨迹 p95 <2s；MQTT 到页面 p95 <3s（100条/s 持续10分钟）；地图1000设备聚合可交互。性能报告必须带数据规模、机器、冷热缓存和成功率。移动端至少测试 390×844，桌面 1440×900。未经实际测量不得宣称达到。

活动体验对标以“登录可用、真实多设备状态、地图/轨迹找设备更快、移动端可用、异常反馈清楚”展示；主办方主观判定不等于自动化测试结果。
